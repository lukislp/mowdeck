# mowdeck-repo-checks

Pytest tests that guard repository conventions. They run as part of `uv run poe test`.

| Check | What it guards |
| --- | --- |
| compose | `infra/compose/docker-compose.yml` parses as YAML and `docker compose config -q` passes (skipped if Docker is missing); Traefik trusts forwarded headers only from `GATEWAY_TRUSTED_PROXIES` (empty by default) on both entry points |
| ADRs | every file in `docs/adr/` named `NNNN-*.md` has Status, Context, Decision, Consequences headings |
| packages | every directory under `services/` and `libs/` has `README.md` and `pyproject.toml` |
| docs | `mkdocs build --strict` succeeds (skipped if mkdocs is not importable) |
| images | every image default in the Dockerfiles (`ARG *_IMAGE`, `FROM`), Compose (`${*_IMAGE:-...}`, snippets) and the CI workflows (service containers, CI-only images) agrees with the `*_IMAGE` lines of `infra/compose/.env.example`; the workflows use no image mirror and the kind test pushes nothing |
| release licences | nothing a release publishes violates a licence: no workflow builds or pushes `integrations/agora-bridge` or the removed `vision-capture` (Agora SDKs, never redistributed); the released Dockerfiles name no Agora SDK (the vision Dockerfile has no capture build any more) and keep `WEB_AGORA_SDK=exclude`; no released Python image depends on an Agora package or Playwright (uv.lock) and the GPL-3.0 adapter only ends up in device-gateway; every released image declares `org.opencontainers.image.licenses` and ships the licence texts under `/usr/share/doc/mowdeck`; the web build runs its bundle guard; every mirrored third-party image has a checked, redistributable licence (`MIRROR_LICENCES`); no Agora binary is committed. `scripts/licence_gate.py` is the release workflow's image gate (job `licence-gate`: Syft SBOM, image file system, web bundle, label) |
| API quota | the workflows stay within `GITHUB_TOKEN`'s 1,000 REST calls per hour: no workflow that builds images uploads Docker build records (`DOCKER_BUILD_RECORD_UPLOAD`), the CI artifacts expire within 7 days, pull request fuzzing runs only for fuzzed paths (every source directory of `.clusterfuzzlite/build.sh` included), the OpenSSF Scorecard runs on a schedule with a concurrency group, and every `gh api`/`gh release` call of `release.yml` and `apple-testflight.yml` goes through `scripts/gh_retry.sh`, whose retry on 403/429/rate limit (and nothing else) is tested against a fake `gh` |
| release signing | every `cosign sign`/`sign-blob`/`attest` of the workflows goes through `scripts/cosign_retry.sh` after a `cosign-installer` step; tested against a fake `cosign`: Rekor 409 conflicts, TUF/CDN fetches, network errors, timeouts, 429 and 5xx are retried (five attempts) with a fresh signature and without the failed attempt's bundle, everything else fails at once, every signature is verified, and a bundle or image signature that already verifies is kept; `release_assets.py notes` replaces the publish job's section of the release notes instead of adding a second one |
| capability matrix | `scripts/capability_matrix.py` (`uv run poe capability-matrix`) renders `docs/reference/capabilities.md` from the installed providers' capability profiles, loaded through the `mowdeck.cloud_providers` and `mowdeck.error_lexicons` entry points (ADR 0071); `test_capability_matrix.py` and the CI docs job (`capability-matrix-check`) fail on a stale page, every installed provider must declare profiles, and the renderer is tested on a fixture provider |
| CI scope | `scripts/ci_scope.py` decides which `ci.yml` jobs a pull request runs (job `changes`, [docs/dev/ci.md](../../docs/dev/ci.md)): the path rules (CI configuration needs no scoped job, shared inputs need every dependent job, an unknown path needs every job), the job-by-job comparison of a changed `ci.yml`, that `ci.yml` has no `paths` filter and every scoped job runs unless its output is `"false"`, that pushes are not scoped, Dependabot's `ci` prefix for GitHub Actions and ClusterFuzzLite bumps next to `fix(deps)` for runtime dependencies, `fix(ci)` releasing nothing (`.github/lktec-bot.yml`) and the release workflow's `release-guard` for CI-only changes |
| app notices | `scripts/app_notices.py` keeps the third-party notices of the native app bundle (`apps/mobile/public/third-party-notices.json`, shown by the app's About page) generated and current: the packages the lock file puts into the app are those of the file, no copyleft, every licence allowed by `apps/mobile/third-party-policy.toml`, no page imports an excluded package; `check --installed` compares with the installed packages (years ignored, versions never named); `ios_release_check.py app` requires the file and the About page in the built bundle |
| source offer | `scripts/source_offer.py` writes a release's `SOURCE-OFFER.md` from the SPDX SBOMs: every GPL, LGPL and AGPL component with version, images and the location of its source (Debian snapshot, Alpine aports, PyPI, upstream, this repository at the tag) after a written three-year offer; the release workflow writes it before the checksums and signatures |

Run on its own: `uv run pytest tools/repo-checks`. On a pull request that leaves the python job out, the CI job `ci-config` runs them (with ruff and mypy on this directory).
